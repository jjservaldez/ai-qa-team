### 2. Suite-level findings

**Coverage gaps**
- AC1, dates changed on the room page calendar: applies. There is no case for which dates get booked when the guest changes the selection on the room page calendar (the UI map shows a selectable calendar).
- AC2: applies. Only short stays are covered. Missing: Price Summary recalculation after the dates change, longer stays, and stays that cross a month boundary (the calendar needs Next).
- AC6: applies. Only invalid formats are tested. There are no positive cases for unusual but valid emails (plus addressing, subdomains, hyphens).
- AC7: applies. Only length is tested. Non-digit characters (+44, spaces, letters) are not covered. The ACs don't say, so the case would have to be marked as an assumption.
- AC10: applies. Missing: a new range that encloses an existing booking (D-1 to D+3), overlap at the start (D-1 to D+1), and a booking that ends on the Check In day of an existing one.
- AC11: applies. Not tested through the URL (checkout ≤ checkin in the query parameters). Past dates are not covered either; the ACs don't say, and the home page is prefilled with today.
- AC12: applies. Only the home-page path and reload are covered. Missing: Similar Rooms "View Details", the breadcrumb, the "Rooms" navigation, and a URL with no or malformed parameters.
- AC9: applies. No case checks the exact confirmation text or format, or the "Return home" button.
- Test data management: applies. No admin access means test bookings can't be cleaned up and created bookings stay. The suite needs a date and room allocation plan, and it can only be run once per allocation.

**Conditions the suite ignores**
- Slow or dropped network during submit: applies. A double submit or a lost response is plausible. It can be simulated with DevTools throttling or offline mode.
- Backend errors: applies. There is no expected behavior for a failed submit request. It can be simulated by blocking the request in DevTools.
- Time of day and time zones: applies. The home page is prefilled with "today" and the calendar highlights today. Bookings starting today near midnight, and a browser time zone different from the server's, could shift dates. Needs verification in the app.
- Two sessions on the same data: applies. Two tabs or browsers submitting the same room and dates at the same moment is not covered (AC10).
- Refresh or Back during or after submit: applies. Only a reload before submit is covered (TC-031). Missing: Back or refresh on the confirmation panel and re-submitting.
- Data that looks valid but isn't: applies. Missing: apostrophes in real names (O'Brien), accents (José), hyphens, emoji (JavaScript may count one emoji as 2 characters at the 18/30 limits), and leading or trailing spaces that push a value across a length boundary. TC-034 uses an apostrophe only as an injection payload.
- Other users of the public demo making bookings: may apply, low confidence. The sources don't say whether the app is shared or reset. Needs verification.
